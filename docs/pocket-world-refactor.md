# 生态舱世界管理重构

日期：2026-11-01；构建标识：`refactor-20261101-pocket10`。目标是把世界归属、空间分配、初始化、补门及拆除清理统一到可核对的边界内。

## 本轮改动

| 职责 | 实现 |
|---|---|
| 世界归属 | `PocketWorldRegistry`：编号必须对应舱体自身的 `WorldContainer`，不再按旧编号接管其它对象；母星从实际位置及其矩形确认 |
| 操作边界 | `PocketWorldBounds`：校验尺寸、网格范围、其它世界矩形、每个格子的 `WorldIdx` 和建筑占格 |
| 空间分配 | `OmniPocketSpaceManager`：只读探测并预留，确认无世界归属、无实际物质和物体后才初始化；新区域保持两格间距，编号耗尽停止创建 |
| 创建与回收 | `PocketWorldLifecycle`：创建、接管、准备和注销统一入口；拆除只处理自身组件及校验过的范围 |
| 布局与补门 | `PocketWorldLayout`：配置区域与日照；缺门时只在空位补门，保留玩家的地形、物品、生物和背景建筑 |
| 诊断与追踪 | `PocketWorldDiagnostics`：界面查询复用准备结果；销毁后清理追踪器，保留空 UI 字典项供界面收尾 |
| 管线及兼容 | 管线方法拆到原组件的 partial 文件；兼容补丁保留原完整类型名，接口增加本舱坐标检查 |
| 旧档高度兼容 | `PocketGridCapacityPatches`：核对原数组长度，准备全部新缓冲后才提交高度和缓冲引用；不修改原始 Sim、Camera 数据 |

## 修改依据

1. 旧代码只用 `targetWorldId` 查世界，没有核对返回对象是否就是本建筑上的组件。世界编号复用时，这不足以证明所有权。
2. `Grid.GetFreeGridSpace` 在返回成功前已经调用模拟接口清空区域。现在探测和预留阶段不修改模拟数据，初始化放在明确的创建步骤中。
3. 原版 `TemplateLoader.Stamp` 的第一阶段会清除范围内拾取物、作物、生物等。旧补门流程重新盖整个真空模板，可能破坏已装修的舱室；现在创建空区域与补门均不走整舱盖模板。
4. 原版 `Grid.FreeGridSpace` 会修改矩形左、右、上侧的 `Grid.Element` 缓存。本轮直接释放自有矩形，并仅在自有格子内更新元素缓存和世界编号。
5. 原诊断查询反复调用准备函数，每次扫描追踪器、分配空列表；销毁清理又通过同一函数重新创建 HUD 追踪器。现在准备按世界及诊断上下文缓存，销毁单独处理。
6. 原高度兼容先改高度，再分配数组。当前游戏 `SaveLoader` 直接把 `GridVisible`、`GridSpawnable`、`GridDamage` 用作网格数组，因此先验证原尺寸并备齐缓冲，再提交，防止普通异常留下部分更新。

这些是源码可确认的风险路径，不等同于证明过去的沙盒、蓝图、卡顿问题全部由它们引起。

## 生命周期

创建：选择有效编号 → 只读验证并预留矩形 → 设置自身世界组件 → 初始化空区域及格子归属 → 核对外部世界 → 配置区域、补门和导航 → 准备诊断 → 发送新世界事件。

拆除：确认组件所有权及完整范围 → 核对舱外位置 → 切换视角、移出复制人 → 原版建筑拆除及资源退回 → 再次核对格子归属 → 释放自有矩形 → 注销世界及追踪器。异常区域停止地形操作，只注销本建筑持有的世界记录，避免把旧编号指向的其它星球一并清理。

退出/读档：进入场景清理状态后，跳过拆舱回收，清空运行时绑定、预留记录及诊断准备缓存。读档未完成时不新建区域；世界注册、注销、改号或重建格子归属时使对应缓存失效。绑定和破坏性操作均拒绝重复世界编号。

## 兼容和限制

- `OmniMod.Buildings.OmniPocketHabitat` 仍是原序列化组件；`targetWorldId`、`hasCleanedLegacyWalls` 字段保持原名和类型。拆成 partial 文件不改变运行时类型。
- 新建外部占地仍为 1×3，内部仍分配 32×32、净空 30×30。现有合法历史舱室按自身保存的范围处理，不重排、不缩放。
- 保留气、液、电接口及原有日照、导航、资源退回规则；补门优先原位置，被占用时寻找本舱空位，不覆盖现有建筑。
- 坐标、归属或旧档缓冲不一致时暂停相关修改，并写明原因。已有的世界重叠、损坏地形和历史蓝图问题不会通过猜测自动修复。
- 本轮约束模组自己的操作，不接管第三方沙盒或蓝图工具。旧档高度兼容保留原 Sim 数据，仍需游戏实际载入确认该版本原生模拟数据的兼容结果。
- 性能探针继续保留。诊断准备缓存去除了可确认的重复工作，实际掉帧改善仍以新日志为准。

验证采用原版程序集调用流程核对、序列化字段与类型名核对、Release 编译及部署文件校验。按用户要求，不启动游戏、不修改存档、不新增测试。
