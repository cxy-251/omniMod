# 机械臂未接单便被零数量拦截（fetch18）

2026-11-02，ONI 744825，构建 `fix-20261102-fetch18`。用户实际运行 `material17` 后，生态舱与第二星球的硫施肥、碎石机原料搬运仍不工作。本轮修正取货任务阶段的数量判断。

## 证据与原因

运行日志确认已加载 `material17`，对应取货补丁没有挂载失败。只读解析第 246 周期存档，中央材料池已有约 `117466.33 kg` 硫，杂物入口没有硫待领取实物；第二星球有实际杂物入口且已勾选硫、砂岩、火成岩等材料。碎石机附近存在原版四格投放范围内的机械臂。这些证据将调查重点从共享库存迁移转到取货任务流程。

已安装游戏程序集中的 `FetchChore` 有两个不同字段：

| 接口 | 原版实际含义与写入时机 |
|---|---|
| `originalAmount` | `requestedamount`，任务构造时写入；查找原料和评估任务时已有值 |
| `amount` | `actualamount`，`FetchAreaBegin(context, amount_to_be_fetched)` 接单后才赋值；新任务评估期间默认 0 |

`EntityPoolAccess.ForChore` 与 `SharedMaterialSupply.ForChore` 都曾用 `chore.amount <= 0` 提前返回，并用它限制出库量。新任务因此无法准备原料，原版无法选择并接单；而没有接单，`amount` 又始终为 0。这形成查找和接单之间的循环阻断，材料共享规则修正并不能消除它。

该错误也影响种子、蛋和其它由 FetchChore 领取的实体；吃饭走独立查询，不属于这条数量判断路径。

## 修改

新增 `SharedFetchRequest.GetAmount`：已有有效接单量时使用接单量；否则读取原始请求量；拒绝无效、非正或非有限数量。实体入口、材料入口的提前退出和出库上限全部使用这个共同接口。本轮不修改房间、世界坐标、箱子共享权限、投放范围、筛选、原版预约或材料温度规则。

新增硫／碎石机任务的三阶段日志，每世界、每类别、每阶段最多二十秒一条：

- `共享取货·候选`：已经找到并准备入口原料，显示原始请求量与当时接单量；这不等同于搬运成功。
- `共享取货·接单`：原版 `FetchAreaBegin` 已执行，机械臂接受了任务，显示实际接单量。
- `共享取货·结束`：原版 `FetchAreaEnd` 的投递成功或取消／失败结果。

接单和结束日志采用独立补丁及异常隔离，不参与原版判断。没有增加全地图扫描或逐物品周期日志。
